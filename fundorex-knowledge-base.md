## 3. Core Capabilities (Deep Dive)

### 3.1 Donation Module
- Users (and the admin) can **create donation campaigns** to raise money for a cause.
- Each campaign is a self-contained fundraising page — title, story, target amount, imagery, social shares, and a donation form.
- Supports both unlimited "ongoing" campaigns and target-based ones.

### 3.2 Event Module
- Admin can publish events on the website.
- Events support **selling event tickets** — useful for galas, benefits, conferences, or community events that double as fundraising.
- Combines well with the donation module for hybrid event + fundraiser pages.

### 3.3 User-Submitted Campaigns (with Admin Approval)
- Any registered user can create their own donation campaign.
- Submitted campaigns are routed to the **admin for approval** before going live — protecting the platform from spam or fraudulent campaigns.
- This is the workflow that makes Fundorex a true *platform* (vs. a single-organization donation page).

### 3.4 Flexible Platform-Fee Configuration
- The admin can configure how the platform earns money on each donation.
- Charge type can be **percentage** or **fixed amount**.
- The fee can be deducted from the **donor's payment** *or* from the **campaign owner's payout** — admin chooses.
- This is what enables Fundorex to be operated as a revenue-generating crowdfunding business.

### 3.5 Emergency Funding Notice
- The admin can mark certain campaigns with an **emergency funding notice** when a campaign owner needs an urgent fund.
- Useful for disaster relief, medical emergencies, or short-deadline causes that need to be highlighted on the site.

### 3.6 Quick Share (Social + Email)
- Each campaign has a **quick share** widget covering the major social platforms plus email.
- Supports the natural growth pattern of crowdfunding: "share with friends and family."

### 3.7 Support Ticketing
- A built-in support ticketing system lets any registered user **raise a ticket** for help.
- Reduces email overhead and gives the platform owner an organized inbox.

### 3.8 Color & Branding Settings
- The admin can change every color on the website from the admin panel — no CSS editing required.
- Combined with the menu / widget / form builders, this makes white-labeling fast.

### 3.9 Newsletter Module
- Built-in newsletter for keeping donors and supporters updated on campaigns, milestones, and new causes.
- Critical for re-activating prior donors when a new campaign launches.

### 3.10 Social Login (Facebook / Google)
- One-click login lets donors register and contribute without typing a password.
- Reduces friction at the most important moment in any fundraiser — checkout.

### 3.11 SEO & Sitemap
- Built-in **sitemap generation** to improve search engine indexing and SEO score.
- Crucial for organic discovery when campaigns are shared widely.

### 3.12 Payment Gateways
- The product page advertises *"Available Payment Gateways"* support.
- Use whichever gateway you've configured to collect donations and ticket payments globally.
- (For exact gateway availability at the time of purchase, refer the buyer to the Envato listing or to Xgenious sales — gateway options can be expanded across versions.)

## 8. Workflow Walkthroughs

### 8.1 Donor workflow
1. Donor visits a campaign page.
2. Donor optionally logs in with Facebook or Google to speed checkout.
3. Donor enters amount and proceeds through a configured payment gateway.
4. The platform fee (if configured to come from the donor) is added on top, otherwise the gross amount is recorded.
5. Donor receives a confirmation; campaign owner is notified.

### 8.2 Campaign-owner workflow
1. User registers / logs in.
2. Submits a new campaign (title, story, goal, media).
3. Campaign goes into "pending" until the admin approves.
4. After approval, the campaign is public and shareable on social platforms / email.
5. Owner sees pledges / donations in their dashboard; payouts respect the fee configuration.

### 8.3 Admin workflow
1. Reviews and approves new campaigns.
2. Configures global fee model (percentage vs fixed; from donor vs from campaign owner).
3. Marks emergency campaigns with the **Emergency Funding Notice** flag.
4. Sends newsletters and answers tickets through the support system.
5. Tweaks colors, menu, forms, widgets via the drag-and-drop builders without writing code.

## 9. Glossary of Crowdfunding Terms

Use this glossary so the AI agent can answer "what is X" type questions without confusion.

- **Campaign** — A single fundraising page with a story, optional goal, and donation form.
- **Donor / Backer** — The person contributing money.
- **Campaign owner / Creator** — The user who created the campaign.
- **Pledge** — A promise to donate (recorded but not always charged immediately).
- **Donation / Contribution** — An actual transferred payment to a campaign.
- **Goal / Target amount** — The fundraising target a campaign aims to hit.
- **All-or-nothing model** — The campaign keeps funds only if the goal is met (Kickstarter-style).
- **Keep-it-all / Flexible funding model** — The campaign keeps whatever it raises (GoFundMe-style).
- **Platform fee** — The cut the platform owner takes from each donation. In Fundorex this is configurable as percentage or fixed amount and can be deducted from donor or campaign owner.
- **Payment gateway** — The processor (PayPal, Stripe, etc.) that actually moves money.
- **Emergency campaign** — A campaign flagged as urgent so it gets surfaced; Fundorex supports this via Emergency Funding Notice.
- **Approval queue** — Pending campaigns awaiting admin moderation before going live.
